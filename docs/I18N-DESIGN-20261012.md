# StickyNotes 国际化（I18N）设计方案

> **文档版本**：v1.0.0
> **日期**：2026-10-12
> **状态**：已批准并实施中
> **参考实现**：`C:\Home\Projects\CarroDesk`（同一作者的成熟实现，约 960 个调用点）

---

## 1. 目标与范围

把散落在 XAML 与 C# 中的**用户可见字符串**集中提取到语言包，使后续新增语言（en-US / ja-JP / …）成为"往 JSON 里加一个文件"的动作，无需改动任何界面代码。

**纳入范围**：XAML 的 `Content` / `Header` / `ToolTip` / `Title` / `Text`，以及 C# 中流向 UI 的字符串（MessageBox、InfoBar、托盘菜单、状态文本、下拉选项）。

**明确排除**：

- `AppLog.*` 日志字符串（156 条）—— 保持中文原样，守住日志检索能力
- XML 文档注释与代码注释（55 条）
- 异常消息（`throw new ...`）—— 保持中文原样，作为开发者诊断信息；同步调整依赖其文案的测试断言
- 便签正文等用户数据

## 3. 技术选型

### 3.1 为什么不用 `.resx` + 卫星程序集

标准 .NET 本地化会产生 `zh-CN/StickyNotes.resources.dll` 卫星程序集，在本项目**不可行**：

1. **Costura 无法嵌入卫星程序集。** 官方文档明确说明：*"Costura cannot embed localization resources (\*.resources.dll) as Costura runs before MS Build can generate them."*（[Fody/Costura#61](https://github.com/Fody/Costura/issues/61)、[Resource.Embedder](https://github.com/francisrc/Resource.Embedder)）
2. **文化名大小写缺陷。** [Fody/Costura#912](https://github.com/Fody/Costura/issues/912) 记录 `zh-Hans` 找不到卫星程序集，需反射改写内部 `assemblyNames` 缓存绕过。
3. **单文件发布破坏解析。** 单文件解压到临时目录，卫星程序集留在原处（[SO71659861](https://stackoverflow.com/questions/71659861)）。
4. **违背项目原则。** `publish.ps1` 走框架依赖便携版；散落的 `zh-CN/` 目录与 `APP-ARCHITECTURE.md` §1.1「轻量即美」冲突。

### 3.2 选定方案：JSON 语言包 + WPF 标记扩展

采纳 CarroDesk 的成熟架构：

| 层 | 实现 |
|---|---|
| 存储 | `src/StickyNotes/Resources/Locales/{code}.json`，分层 JSON + `_meta` 块 |
| 嵌入 | `<EmbeddedResource Include="Resources\Locales\*.json" />` —— 进主程序集清单资源，Costura 不介入 |
| XAML | `{loc:Loc Key, Default='原文'}` 标记扩展 |
| C# | `Loc.T(key)` / `Loc.T(key, default, args)` / `Loc.Format(key, args)` |
| 外部语言包 | 启动时扫 `<数据目录>/lang/*.json`，**发版后加语言无需重编译** |

**为什么优于 XAML ResourceDictionary 方案**：翻译者只碰 JSON、不碰 XAML；`Default='原文'` 让中文原文留在调用点便于 review 与 diff；支持 `auto` 跟随系统；支持发版后补语言。

### 3.3 相对 CarroDesk 的四处修正

| # | CarroDesk 现状 | 本项目修正 |
|---|---|---|
| 1 | 契约测试只扫 `*.cs` 的 `Loc.T(...)`，**XAML 的 384 个 `{loc:Loc}` 调用点完全未校验** | 正则补 `{loc:Loc ([A-Za-z0-9_.]+)`，并遍历 `*.xaml` |
| 2 | `catch { }` 静默吞掉 JSON 解析异常，键集合归零后全站退化且无日志 | 用 `AppLog.Error` 显式记录 |
| 3 | 回退链为「当前 → 另一种语言 → default → key」，三种语言以上会中英日混排 | 改为「当前 → **zh-CN（源语言）** → default → key」 |
| 4 | 无"裸中文字面量"守卫，实测残留 129 条无人察觉 | 增加守卫测试 |

## 4. 架构设计

### 4.1 目录布局

```
src/StickyNotes/
├── Resources/
│   └── Locales/
│       ├── zh-CN.json          # 源语言（中文，现有文案迁移基准）
│       └── en-US.json          # 英文
├── Services/
│   ├── Localization/
│   │   ├── I18nService.cs      # 语言包加载 + 查询 + 语言切换
│   │   ├── Loc.cs              # 静态门面（C# 侧入口）
│   │   └── LocExtension.cs     # WPF 标记扩展（XAML 侧入口）
```

### 4.2 语言包结构

分层 JSON，`_meta` 声明语言代码与显示名；`FlattenJson` 递归展开为点号键：

```json
{
  "_meta": { "code": "zh-CN", "name": "简体中文" },
  "Common": {
    "Ok": "确定",
    "Cancel": "取消",
    "Error": "错误"
  },
  "Tray": {
    "Title": "彩色便签",
    "Exit": "退出"
  }
}
```

键路径：`Common.Cancel`、`Tray.Exit`。

### 4.3 C# 侧 API

```csharp
public static class Loc
{
    public static string T(string key);
    public static string T(string key, string defaultValue);
    public static string T(string key, string defaultValue, params object[] args);
    public static string Format(string key, params object[] args);
    public static string CurrentLanguage { get; }
}
```

### 4.4 XAML 侧 API

```xml
<Button Content="{loc:Loc Tasks.Save, Default='保存'}"
        ToolTip="{loc:Loc Tasks.SaveTooltip, Default='保存当前任务'}"/>
```

`LocExtension.ProvideValue` 在 `TargetObject` 是 `DependencyObject` 时生成
`Binding { Source = I18nService.Instance, Path = "[Key]", Mode = OneWay }`；
语言切换时 `I18nService` 发 `PropertyChanged("Item[]")` 触发全部绑定重算，实现热刷新。

非 `DependencyObject` 场景（部分 `Setter` / 设计器求值）退化为静态字符串，不参与热刷新；
此类需在代码构建的 UI 中由 `LanguageChangedMessage` 显式刷新。

### 4.5 语言切换链路

```
设置页语言下拉
   → SettingsService.Language setter（原子写 settings.json）
   → WeakReferenceMessenger 发 LanguageChangedMessage(lang)
   → I18nService.ApplyLanguage(lang)
       ├─ 切换字典（当前 → zh-CN → default → key）
       ├─ Thread.CurrentThread.CurrentUICulture = ...
       ├─ PropertyChanged("Item[]")  → 刷新全部 {loc:Loc} 绑定
       └─ 广播事件 → 代码构建 UI（托盘菜单）手动刷新
```

### 4.6 语言偏好持久化

`AppSettings` 新增：

```csharp
/// <summary>界面语言（auto / zh-CN / en-US），auto 表示跟随系统</summary>
public string Language { get; set; } = "zh-CN";
```

- 默认 `zh-CN` 而非 `auto`：**老用户升级后界面语言必须不变**，这是兼容性底线。`auto` 作为设置页可选项存在。
- `System.Text.Json` 反序列化时缺失字段自动取默认值，老 `settings.json` 无需迁移。

### 4.7 外部语言包

启动时扫描 `Path.Combine(AppPaths.DataDirectory, "lang")` 下的 `*.json`，同 `_meta.code` 覆盖内置版本。便携模式下自动落在 `app_data/lang/`。

## 5. 键命名规范

`模块.区域.语义`，层级与 UI 结构对齐：

```
Common.Ok / Common.Cancel / Common.Delete / Common.Error
Tray.NewNote / Tray.Open / Tray.Exit
Settings.FontSize.Label / Settings.IdleLock.Enable
Sync.Now / Sync.Failed / Sync.ServerIncomplete
Pin.Setup / Pin.Forgot / Pin.Mismatch
Note.EmptyPreview
Search.ResultCount        // "找到 {0} 条匹配便签"
```

**占位符**统一使用序号索引 `{0}` `{1}`，不用内插，保证非英语系语序可调：

```json
"ResultCount": "找到 {0} 条匹配便签 (回车或点击直达)"
```

## 7. 质量守卫（P5）

标记扩展的致命点是**键拼错时静默无异常**。必须补齐四类契约测试：

| 测试 | 作用 |
|---|---|
| `Locales_KeySets_Match` | 各语言包键集合完全一致（缺键会静默回退，肉眼难察） |
| `Locales_Placeholders_Match` | 同一键在各语言的 `{n}` 占位符集合一致（否则某语言显示字面量 `{0}`） |
| `Locales_EveryReferencedKey_IsDefined` | 扫描**全部 `*.cs` 与 `*.xaml`** 的 `Loc.T(...)` 与 `{loc:Loc X}` 调用，校验键存在 |
| `Xaml_No_HardcodedChinese` | XAML 中不得出现未走 `{loc:Loc}` 的裸中文字面量（防回退） |

契约测试直接读源码树中的语言包，不为测试在 `I18nService` 上开放诊断接口。

## 8. 已知限制

1. **非 `DependencyObject` 场景不热刷新**：`Setter` / 设计器求值路径返回静态字符串。此类 UI 需由 `LanguageChangedMessage` 显式刷新。
2. **异常消息不本地化**：UI 中若直接透出 `ex.Message`，用户会看到中文错误（英文界面下）。属已知取舍 —— 优先保证日志与诊断信息可读。后续如需改善，应在 UI 边界做错误码 → 本地化文案的映射，而非翻译异常本身。
3. **`auto` 跟随系统**：目前 `ResolveLanguageCode` 仅区分 `zh*` / `en*`，其余一律回 `en-US`。扩充语言时需同步该函数。
