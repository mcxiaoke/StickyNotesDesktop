# 2026-10-11 20:55:15 (GMT+8) — PIN 改为会话级闲时锁定

## 变更摘要

- **新增** `Services/SessionLockCoordinator.cs`（单例）：进程内唯一的锁定状态源。以「无键鼠输入时长」判定闲置，
  1 秒 tick 的 `DispatcherTimer` 常驻计时（不依附任何窗口，托盘隐藏期间照样计时）；
  活动源为 `InputManager.Current.PreProcessInput`；`SystemEvents.SessionSwitch` 遇锁屏立即强制上锁。
  internal 构造可注入假时钟，使超时判定在毫秒级完成且完全确定。
- **修复（核心）** `NotesListWindow` 在 `IsVisibleChanged` 变为可见时无条件 `IsLocked = true` ——
  导致「X 关到托盘 → 再打开必输 PIN」，且 `ListAutoCloseMinutes` 从不参与锁定判定，
  设置里改成 1 分钟或 30 分钟对「要不要输 PIN」完全等价。现改为只同步会话锁状态，不再自行判定。
- **修复** 「闲时」口径错误：原 `Deactivated`/`Activated` 计的是窗口不在前台的时长，
  人离开但窗口仍停在前台时**永远不上锁** —— 恰是防偷窥最需覆盖的场景。改为全局输入计时后已覆盖。
- **修复** 跨窗口解锁不一致：`ArchivedNotesWindow` 为 Transient，原先每次打开都新建并探测主列表解锁状态，
  探测失败会**额外再要一次 PIN**；现由会话锁共享单一状态，解锁一次全会话解锁。
- **修复** 两个受保护窗口只订阅了 `LockRequested`：在归档窗口输了 PIN 后主列表遮罩仍不消失。现两个方向都订阅。
- **设置项重做**：`ListAutoCloseMinutes`（不在前台自动关闭）移除，替换为
  `IdleLockMinutes`（闲置自动锁定，0/1/5/10/30/60，默认 10）与 `LockOnLaunch`（启动时锁定，默认开启）。
  旧项只负责隐藏窗口，而隐藏必然导致下次打开重新锁定，正是本次痛点的来源。
- **冷启动锁定**：`LockOnLaunch` 默认开启，进程一启动即锁定。这是防「托盘退出 → 重新双击 exe 绕过锁定」
  的唯一防线 —— 该绕过路径与闲置时长无关，必须单独设防。
- **吸收态**：一旦锁定，`NotifyUserActivity` 只刷新时间戳而不解锁（否则点一下遮罩就白锁）；
  唯一解锁入口是 PIN 验证成功后的 `Unlock()`。
- **假安全防护**：`IdleLockMinutes == 0 && !LockOnLaunch && PIN 已启用` 时设置页以危险色显式告警；
  同时常驻显示「当前锁定范围：管理中心列表窗口与归档管理窗口；桌面便签不受保护」——
  桌面便签不上锁是产品有意决策，此前设置页未说明，导致用户误判（review 文档 676 行未决项）。
- **遮罩文案**：新增 `PinLockReason`（SessionStart / IdleTimeout / ScreenLock），自动锁定时提示
  「长时间未操作，已自动锁定」，与冷启动锁定区分。
- **DI**：`AddSingleton<SessionLockCoordinator>()` 置于各窗口之前；`App.OnStartup` 显式解析一次，
  确保 `--autostart`/`--minimized` 路径下冷启动锁定同样生效。实例由 `ServiceProvider.Dispose()` 统一退订钩子。

## 行为变化

| 场景 | 改前 | 改后 |
|------|------|------|
| 冷启动 / 托盘退出后重开 exe | 要输 PIN | 要输 PIN（不变，且改为由开关控制） |
| X 关到托盘 → 再打开 | **要输 PIN** | 不用输 |
| 闲置超阈值 → 打开或切回 | 取决于是否被隐藏过 | 要输 PIN |
| 闲置超阈值 → 窗口停在前台无人操作 | **永不锁** | 要输 PIN |
| 锁屏 | 不锁 | 立即锁 |
| 第二实例唤醒（进程仍在） | 要输 PIN | 不用输 |

## 遗留 / 未纳入本次范围

- **桌面便签（NoteWindow）不上锁**：`NoteWindow.xaml` 无 `PinLockOverlay`，贴在桌面上的正文始终是明文。
  本次经确认暂不纳入，已在设置页写明范围。若后续要做，需处理无边框自定义窗口的遮罩层与锁定时的拖动禁用。
- **PIN 无失败次数限制 / 冷却**：暴力破解仍可无限尝试，属既有能力边界，本次未动。
