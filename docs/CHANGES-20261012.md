### 关键技术决策：为何不用 `.resx` 卫星程序集

经查证，标准 `.resx` 本地化在本项目**不可行**：

1. **Costura 无法嵌入卫星程序集** —— 官方文档明示 *"Costura cannot embed localization resources (\*.resources.dll) as Costura runs before MS Build can generate them."*（Fody/Costura#61）
2. **文化名大小写缺陷** —— `zh-Hans` 找不到卫星程序集（Fody/Costura#912）
3. **单文件发布破坏解析** —— 解压根目录与卫星程序集所在目录不一致（SO71659861）
4. **违背项目原则** —— 与 `APP-ARCHITECTURE.md` §1.1「轻量即美、目录整洁」冲突

改为 `<EmbeddedResource Include="Resources\Locales\*.json" />`。**已实测验证**：发布产物根目录无任何语言散目录，主程序集清单资源含
`StickyNotes.Resources.Locales.{zh-CN,en-US}.json`，Costura 资源未受影响。

### 行为变更（需留意）

1. **`AppSettings` 新增 `Language` 字段**，默认 `zh-CN`（非 `auto`）。
   老用户升级后界面语言保持不变；`System.Text.Json` 对缺失字段自动落默认值，旧 `settings.json` **无需迁移**。
2. **设置页「外观与显示」新增「界面语言」下拉**，首项「跟随系统 (Auto)」，其余为已加载语言包的自报原生名。修改即生效，无需重启。
3. **语言在 `App.OnStartup` 中于数据库初始化之前应用**，故「启动失败」弹窗也使用用户选定语言；语言加载失败仅记日志，绝不阻断启动。
4. **新增外部语言包目录** `<数据目录>/lang/*.json`，同语言代码覆盖内置版本 —— 发版后可补语言而无需重新打包。便携模式下自动落在 `app_data/lang/`。

### 热切换刷新链路

`{loc:Loc ...}` 绑定由 `I18nService` 的 `PropertyChanged("Item[]")` 自动刷新。以下**非可观察的计算属性**已通过 `LanguageChangedMessage` 显式接线：

| 组件 | 刷新方式 |
|---|---|
| `SettingsViewModel` | `RefreshLocalizedText()` 重发 8 个属性 |
| `SyncSettingsViewModel` | `RefreshLocalizedText()`，与 `DetachSyncHostEvents` 对称退订 |
| `NotesListViewModel` | 重发搜索状态；逐条 `Note.NotifyLocalizedTextChanged()`；`SearchResults` 清空重加以强制容器重建（`SearchHit` 为不可变 record） |
| `ArchivedNotesViewModel` | 逐条通知 + `NotifyDerivedCollectionsChanged()` |
| `NoteViewModel` | 重发 `SaveStatusText` |
| `TrayIconService` | `RefreshTrayTexts()` 改写托盘 ToolTip 与 4 个菜单项 Header |
| `PinLockOverlay` | 按当前锁定原因重算提示文案 |

`Note` 新增 `internal NotifyLocalizedTextChanged()`：其 `PreviewText` / `DisplayTitle` 是按需计算属性，不参与 `SetProperty`。

### 后续可扩展项

1. 新增语言：放入 `Resources/Locales/{code}.json` 并在 `csproj` 的通配符中自动纳入，翻译后即可发布。
2. 异常消息本地化：需先在 UI 边界建立「错误码 → 本地化文案」映射，不宜直接翻译异常本身（会牺牲日志可读性）。
3. `ResolveLanguageCode` 目前仅做语言前缀匹配，扩充语言时需同步维护。
